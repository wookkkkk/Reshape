多数屏对应 shared/src/commonMain/kotlin/com/woo/kuiklycomposetemplate/session/ 下的 Composable。文案、数值、间距都取自 Kotlin 代码：dp / sp 按 1:1 映射成 px，颜色来自 SessionTheme.kt 的 object S， 训练内容来自 SessionModel.kt 的 glutesLegsSession（臀腿 · 5 个动作 · 17 个组位，含热身）。 顶部画出 iOS 状态栏和小程序胶囊，是因为 Kotlin 侧的顶栏留白 （statusBarHeight + S.capsuleHeight、S.capsuleReserve）就是为它们让位的。 改设计稿之前先对一遍对应的 Composable，避免两边对不上。

「动作配置」（已合并原「编辑动作」与「新建自定义动作」）支持「计划编排」与「练中临时添加」双场景，包含杠铃片算盘、器械孔位备忘及生效范围；「休息时长」为辅助设计稿。

「三大项数据」「训练原则」「完整计划」「三个训练日」及「本周期递进」对应 KaishengwangXTanchengyi， 该仓库已经落到本地 com/woo/kuiklycomposetemplate/training/， 所以这几屏的文案和数值直接取自 Kotlin 而不是上游 TS： 动作内容来自 TrainingPlan.kt 的 trainingPlan（3 个训练日 × 5 个动作，共 15 个）， 卡片结构照 ExerciseCard.kt，建议重量徽标的三种颜色对应 WeightDisplay.kt 里 LINEAR / SEMI / FIXED 三个分支。 推算链路是 三大项 1RM → 动作系数 → 目标次数对应的 RPE 8 百分比 → 取整到 2.5 kg → 按本周期第几次训练 +2.5 kg（WeightCalculator.kt）。 所有建议重量都是按 深蹲 90 / 卧推 70 / 硬拉 120 跑一遍该算法算出来的，不是估的。 这套东西在这里不是独立的一块，而是叠在原有逐组记录流程上的建议重量层 —— 记录页的步进器仍然可以随手改，建议值只负责给一个起点。

训练日三屏里的橙色「实现注意」块不是给用户看的文案， 是照着算法跑数时发现的边界：parseTargetReps 只取 reps 字符串里的第一个数字， 自重动作（双杠臂屈伸、山羊挺身）的系数表达不了「总负荷 vs 外加配重」， 带组内 rest-pause 的动作也没法用单一组间休息时长描述。真要实现先解掉这几条。

标了 v2 的页面是深度融合十年以上力量训练实战体验的优化稿： 一、热身组与正式组隔离：支持一键生成热身阶梯，热身不污染正式容量与 RPE 自动调节； 二、同组镜像与历史天花板 PR：每组输入下方对标上次同组表现与历史个人最佳纪录； 三、数字大键盘与快捷配重：点击大字直呼九宫格大键盘，支持 +2.5/+5/+10 快捷加片； 四、单侧动作弱侧保护：单腿/单手动作分别记录左右次数，以弱侧定有效正式组； 五、肌群超量恢复雷达与出门装备清单：科学指引部位恢复状态，出门前提醒腰带/护膝/拉力带； 六、灵活调度与超级组穿插：支持临时插入休息日、调换部位及一键绑定孤立超级组； 七、老铁极简纯黑硬核战报卡：结算页一键生成纯黑高对比度战报图与文本，方便打卡交流。
